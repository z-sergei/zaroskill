# Защита clean_display_name

Ведущий навык — `khorikov-unit-testing`. Проверяемая граница — реальная чистая функция: строка Python → очищенная строка либо `ValueError`. Ожидания основаны на `task.md`; изменение интерфейса ввода не даёт основания менять правила очистки. Production не менялся, моки и новая инфраструктура не нужны.

Исходные семь тестов уже содержат полезные различия:

- `"A"` принимается без смены регистра: минимальная допустимая длина и сохранение uppercase.
- Двадцать символов с внешними пробелами, табуляцией и переводом строки принимаются после очистки: верхняя включительная граница и порядок «очистить, затем измерить».
- Пустая строка и строка только из пробелов/табуляции/перевода строки отклоняются: это разные исходные формы, позволяющие обнаружить проверку пустоты до очистки.
- 21 ASCII-символ отклоняется: верхняя запрещённая граница.
- `Ada  LoVELace` сохраняет регистр и внутренний двойной пробел: нельзя нормализовать case или схлопывать пробелы.
- Двадцать `é` принимаются: длина считается не в UTF-8 байтах.

Сохранены все эти проверки. Новые многочисленные ASCII-примеры, проверки неподдерживаемых типов и UI-тесты по одной только гипотезе о будущем интерфейсе не добавлены.

## Два конкретных дополнения

1. `test_unicode_whitespace_is_trimmed_from_edges`: неразрывный пробел U+00A0 и em space U+2003 по краям имени удаляются. Контракт ссылается на `str.strip()`, а прежний набор допускал замену на очистку только ASCII whitespace. Риск реален для переписывания входного фильтра. Ожидается буквальная строка `Ada`, а не значение, вычисленное вызовом того же production.
2. `test_combining_characters_are_preserved_and_count_towards_length`: десять пар `e` + U+0301 (20 элементов строки Python) возвращаются без преобразования; ещё одна `e` даёт 21 и должна быть отклонена. Прежний пример `é` различает символы и байты, но не символы Python и графемы. Новый сценарий также обнаруживает нежелательную Unicode-нормализацию перед возвратом. Это одно связное различие на границе 20/21, а не перебор алфавитов.

## Проверенная ценность и стоимость

Защита от регрессий усилена для двух явно названных правил. Устойчивость к рефакторингу сохраняется: тесты видят только публичный результат и исключение; корректная внутренняя реализация может меняться. Обратная связь быстрая и детерминированная, без I/O, времени и случайности. Поддержка — два небольших теста с видимыми входами и одним пояснением комбинируемого символа. Не требуется таблица всех Unicode whitespace или библиотека графем.

Фактически выполнено `PYTHONDONTWRITEBYTECODE=1 python3 -m unittest discover -v` из папки случая: до изменений 7 тестов OK; после — 9 тестов OK, exit 0. `python3` используется, потому что команда `python` отсутствует.

В одноразовой копии `probes/02_ascii_strip` изменён только `raw.strip()` на очистку явного набора из шести ASCII-пробельных символов. Исходные 7 тестов прошли; после переноса усиленного набора выполнены 9 тестов, только новый сценарий Unicode-краёв упал с неизменёнными пробелами вместо `Ada` (exit 1). Так конкретный пропуск и его устранение наблюдались реально. Production случая всё время оставался исходным и отдельно прошёл итоговый набор. Полный вывод сохранён в корневом `execution.md`.

Для ошибочного подсчёта графем и Unicode-нормализации приведено различающее рассуждение, отдельная мутационная проба не исполнялась. Проверки относятся к функции валидации, а не к тому, вызывает ли её будущий интерфейс: такой интеграционный контракт вне доступной задачи.
