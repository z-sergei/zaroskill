# Ограничение скидки выполнено через два наблюдаемых TDD-цикла

`discounted_total` принимает keyword-only `max_discount_cents=None`. Сначала проверяются прежние ограничения и отрицательный лимит, затем вычисляется целая скидка; при заданном лимите она ограничивается через min. Вызовы без аргумента и с None сохраняют прежний расчёт. Не добавлены зависимости, слои, ограничения на вне-контрактные типы или проверки внутренних деталей.

Требования взяты из task.md; других production-потребителей в самостоятельной папке нет. Проверяется результат реальной функции существующим unittest. Все шесть соседних тестов сохранены без изменения ожиданий.

| Требование | Пример и наблюдение | Проверка / статус |
| --- | --- | --- |
| Ограничить скидку, а не итог | 1000, 15%, cap 100 → 900 | test_cap_limits_the_discount_not_the_total; RED → GREEN |
| Отрицательный лимит всегда запрещён | cap −1 при (1000,15), (1000,0), (0,100), (1,1) → ValueError | test_negative_cap_is_rejected_even_when_discount_is_zero; RED → GREEN |
| Нулевой лимит разрешён | 1000, 100%, cap 0 → 1000 | test_zero_cap_leaves_the_subtotal_unchanged; сразу GREEN после реализации |
| Равный и больший лимит не увеличивают скидку | 1000, 15%, cap 150 или 200 → 850 | test_cap_at_or_above_the_discount_preserves_the_calculation; сразу GREEN |
| Округление вниз сохраняется с лимитом | 999, 15%, cap 200 → 850 | тот же параметризованный тест; сразу GREEN |
| Явный None сохраняет расчёт | 999, 15%, None → 850 | test_none_cap_preserves_the_uncapped_calculation; сразу GREEN |
| Только keyword-аргумент | третий позиционный аргумент → TypeError | test_cap_must_be_passed_by_keyword; сразу GREEN |
| Прежние вызовы, границы процентов и суммы | 0%, 15%, 100%, округление, неверные subtotal/percent | шесть исходных тестов; GREEN до и после |

Выбор примеров различает отдельные ошибки: ограничение итоговой цены вместо скидки, игнорирование лимита, увеличение скидки до лимита, ошибочный truthiness для нуля, округление вверх, подсчёт negative cap после раннего возврата при нулевой скидке. Для последнего проверены нулевой процент, нулевая сумма и округление малой скидки до нуля: это разные правдоподобные ранние выходы. Ожидания буквальные и получены из условия (например, 999 × 15 // 100 = 149, итог 850), без повторения алгоритма в тестовом helper.
