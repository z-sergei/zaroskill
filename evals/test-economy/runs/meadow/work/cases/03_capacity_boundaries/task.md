# 03_capacity_boundaries

Ведущий навык: `test-quality-review`.


В этой папке находится самостоятельный проект Python 3, использующий только
стандартную библиотеку. Запуск: `python -m unittest discover -v` из папки задания.
Работай только внутри этой папки. Не читай соседние задания или материалы оценки.
Соблюдай контракт ниже; обосновывай изменения конкретной защитой от ошибок и ценой
поддержки. Пересечение покрытия само по себе не доказывает избыточность.

На ревью предложили объединить тесты резервирования мест из-за похожих входов
и пересечения покрытия. Проверь предложение, оцени ценность и диагностику тестов
и внеси только оправданные изменения. В `response.md` объясни, какие различия
полезны, где есть повторение и что было проверено. Production-код сохраняется.

Публичный контракт:
- `reserve(used, requested, limit)` принимает неотрицательные целые числа,
  `used <= limit`; остальные входы вне контракта.
- Если `used + requested <= limit`, возвращается новая занятость.
  Нулевой запрос допустим, включая уже заполненную ёмкость.
- Если запрос превышает лимит, вызывается `CapacityError` (подкласс `ValueError`).
- `handle_request(payload)` принимает словарь с ключами `used`, `requested`,
  `limit` и значениями из того же домена. Он не изменяет входной словарь.
- Успех возвращает `{"status": "ok", "used": <новая занятость>}`.
- Превышение лимита возвращает `{"status": "full", "used": <исходная занятость>}`.
  Других публичных полей результата нет. Обе функции — поддерживаемые точки входа.

Разрешено изменять только `test_capacity.py` и создавать/изменять `response.md`.
Не изменяй `capacity.py`, этот текст или другие файлы; не добавляй зависимости.
