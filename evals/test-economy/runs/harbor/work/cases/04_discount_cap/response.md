# Результат

Добавлен необязательный keyword-only `max_discount_cents=None`. После прежней валидации отдельно отклоняется отрицательный лимит; целочисленная процентная скидка ограничивается `min(discount, cap)` только для заданного лимита. Возвращается исходная сумма минус скидка. Внешних зависимостей и новой архитектуры нет; рефакторинг не понадобился.

Проверяемая граница — публичная чистая функция. Ожидания взяты из `task.md` и посчитаны независимо: 30% от 1000 = 300, при лимите 200 итог 800; 15% от 999 округляются вниз до 149, итог 850. Подмены не нужны.

| Требование | Свидетельство |
| --- | --- |
| Вызов без лимита, 0%, 100%, обычная скидка, округление | Сохранены четыре исходных успешных теста |
| Недопустимые сумма/процент | Существующие два теста расширены на `None` и нулевой лимит: лимит не должен обходить старую валидацию |
| Лимит меньше скидки ограничивает именно скидку | `test_discount_cannot_exceed_the_cap`: 1000, 30%, cap 200 → 800; наблюдался red/green |
| Отрицательный лимит, в том числе нулевая скидка | `test_negative_cap_is_invalid_even_when_the_discount_is_zero`: cap -1 при 0% и 30%; наблюдался red/green |
| Явный `None` сохраняет расчёт | 999, 15%, None → 850; сразу green |
| Лимит выше скидки не увеличивает её | 999, 15%, cap 200 → 850; сразу green, заодно сохраняет округление при заданном лимите |
| Нулевой лимит допустим | 1000, 30%, cap 0 → 1000; сразу green |
| Новый аргумент только по имени | Третий позиционный аргумент вызывает `TypeError`; сразу green |

Реальная последовательность (полный журнал также в корневом `execution.md`):

1. `PYTHONDONTWRITEBYTECODE=1 python3 -m unittest discover -v`: исходные 6 тестов, `OK`.
2. Новый тест ограничения запущен до изменения production: ошибка неизвестного keyword. Это обнаружение отсутствующего API, а не содержательный assertion red.
3. Добавлена только сигнатура с игнорируемым аргументом. Повторный запуск того же теста: `AssertionError: 700 != 800`, exit 1. Скидка ещё не ограничивалась.
4. Добавлено ограничение `min`. Тот же тест: `OK`; общий набор 7 тестов: `OK`.
5. Добавлен тест отрицательного лимита. Он дал два `ValueError not raised`, exit 1, при 0% и 30%.
6. Добавлена проверка отрицательного лимита. Тот же тест: `OK`; общий набор 8 тестов: `OK`.
7. Добавлены четыре остальных проверки нового контракта и расширены два старых отклонения. Общий набор: 12 тестов, `OK`, exit 0. Они подтвердили уже реализованное поведение, отдельный red для них не заявляется.

Соседние тесты обычного расчёта использованы повторно; не создан второй дублирующий набор старых правил. Каждый новый пример различает конкретную ошибку: игнорирование лимита, ограничение итога вместо скидки, вычитание лимита без `min`, смешение нуля и `None`, пропуск валидации или изменение формы вызова. Пример равенства лимита и скидки отдельно не добавлен: он не отличает результат от уже проверенных сторон правила `min`. Тесты других типов не добавлены — они вне контракта. Выполненный red/green повторно fault-probe не дублировался.
