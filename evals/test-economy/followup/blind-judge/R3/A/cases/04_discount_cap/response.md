# Результат

Добавлен keyword-only `max_discount_cents=None`: скидка ограничивается через `min`, отрицательный лимит проверяется до расчёта. Исходные шесть тестов и старый алгоритм округления сохранены.

## Реальные проверки

Все команды выполнены из этой папки с `PYTHONDONTWRITEBYTECODE=1`.

1. `python -m unittest discover -v` — интерпретатор `python` отсутствует (код 127). Это не поведенческий red.
2. `python3 -m unittest discover -v` до изменения — 6 тестов, OK.
3. После добавления первого теста и только объявления параметра: `python3 -m unittest -v test_discounts.DiscountTests.test_discount_cannot_exceed_cap` — FAIL, `850 != 900`. Лимит принимался, но ещё не ограничивал скидку. После добавления `min` тот же тест прошёл; полный набор — 7 тестов, OK.
4. `python3 -m unittest -v test_discounts.DiscountTests.test_negative_cap_is_rejected_even_without_discount` до проверки отрицательного лимита — FAIL во всех 4 примерах, `ValueError not raised`. После добавления валидации тот же тест прошёл; полный набор — 8 тестов, OK.
5. После остальных контрактных примеров `python3 -m unittest discover -v` — 13 тестов, OK. Эти дополнительные примеры сразу прошли и не выдаются за отдельные red–green циклы.

## Выбор тестов

Источник ожиданий — `task.md`; проверяется публичная функция, внешних эффектов нет. Ожидания вычислены вручную: 15% от 999 округляется до 149, поэтому итог равен 850.

| Требование и риск | Пример | Тест / свидетельство |
| --- | --- | --- |
| Совместимость вызовов без лимита | Процент, округление, 0% и 100%, неправильные входы | Все 6 исходных тестов сохранены |
| Ограничивается скидка, а не итог | 1000, 15%, лимит 100 → 900 | `test_discount_cannot_exceed_cap` |
| Явный `None` не ломает вычисление | 999, 15%, `None` → 850 | `test_none_cap_preserves_rounded_percentage_discount` |
| Лимит не превращается в обязательную скидку | 999, 15%, лимиты 149 и 150 → 850 | `test_cap_at_or_above_discount_keeps_percentage_discount` |
| Ноль не трактуется как отсутствие лимита | 1000, 100%, лимит 0 → 1000 | `test_zero_cap_prevents_discount` |
| Отрицательный лимит запрещён без исключений для нулевой скидки | `(0,0)`, `(0,100)`, `(1000,0)`, `(1000,15)` с `-1` → `ValueError` | `test_negative_cap_is_rejected_even_without_discount` |
| Сохранён keyword-only контракт | Третий позиционный аргумент → `TypeError` | `test_cap_must_be_passed_by_keyword` |
| Ранний возврат при нулевом лимите не обходит валидацию | Отрицательная сумма, проценты -1 и 101, лимит 0 → `ValueError` | `test_zero_cap_does_not_bypass_subtotal_or_percent_validation` |

Новые тесты защищают разные нарушения контракта; совпадение части вычислений со старыми тестами не причина удалять их. Цена поддержки — семь коротких тестовых методов со значениями и небольшими таблицами, без моков, зависимостей и привязки к внутренним деталям. Не нужны новая архитектура, дополнительные уровни интеграции или проверки типов вне контракта. Итоговые файлы просмотрены: исходные ожидания не ослаблены, незакрытых требований нет.
