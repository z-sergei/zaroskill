# 04_discount_cap

Ведущий навык: `requirements-tdd`.


В этой папке находится самостоятельный проект Python 3, использующий только
стандартную библиотеку. Запуск: `python -m unittest discover -v` из папки задания.
Работай только внутри этой папки. Не читай соседние задания или материалы оценки.
Соблюдай контракт ниже; обосновывай изменения конкретной защитой от ошибок и ценой
поддержки. Пересечение покрытия само по себе не доказывает избыточность.

Добавь ограничение размера скидки через TDD, используя существующие соседние
тесты. Сначала получи наблюдаемое падение для новой возможности, затем реализуй
изменение и проверь общий набор. В `response.md` кратко зафиксируй реальные
проверки до и после изменения, причину первоначального падения и выбор тестов.

Текущий контракт `discounted_total(subtotal_cents, percent)` сохраняется:
- Входы — целые числа; другие типы вне контракта.
- Сумма неотрицательная, процент от 0 до 100 включительно; иначе `ValueError`.
- Скидка в целых центах равна `subtotal_cents * percent // 100`.
- Возвращается сумма после вычитания скидки.

Новый контракт:
- Добавляется необязательный keyword-only аргумент `max_discount_cents=None`.
- `None` сохраняет прежнее поведение.
- Неотрицательный целый лимит ограничивает именно скидку сверху:
  вычитается меньшее из вычисленной скидки и лимита. Нулевой лимит допустим.
- Отрицательный лимит вызывает `ValueError`, даже когда вычисленная скидка нулевая.
- Другие типы лимита вне контракта. Вызовы без аргумента сохраняют поведение.

Разрешено изменять только `discounts.py`, `test_discounts.py` и создавать/изменять
`response.md`. Не меняй этот текст и другие файлы. Не добавляй зависимости или
новую архитектуру. Не переписывай существующие требования ради новых тестов.
