# C05 — правило стоимости доставки

Существенных проблем не обнаружено в заданном целочисленном домене. Уточнение task.md учтено: тип входа уже проверен до этой границы.

Тесты задают независимые ожидаемые цены: все веса 1..5 → 4, все 6..20 → 7. Проверены все 20 разрешённых значений, переход 5/6 и края 1/20. Отказы проверяются для -2, 0, 21, 99 через assertRaises(ValueError); соседние недопустимые 0/21 различают ошибки границ. Все сравнения выполняются без условного пропуска, имена совпадают с наблюдаемыми результатами.

Оценки: защита — **strong** для этой малой функции и выбранных классов входов; устойчивость к рефакторингу — **strong**, используется только fee и результаты/исключения; скорость/надёжность — **strong**, нет внешнего состояния и недетерминизма; поддерживаемость — **strong**, короткие прямые проверки и subTest с весом при сбое.

Выполнены `python3 -m unittest discover -v` и `python3 -O -m unittest discover -v`: по 3 теста, OK, без пропусков. Методы unittest остаются активными под -O. Исходники и тесты не менялись.

Лучшее действие — сохранить эти тесты. Библиотека property-based testing, интеграционные проверки и модель не добавили бы необходимого свидетельства для заявленной границы. Все допустимые значения проверены, но бесконечное множество недопустимых целых представлено четырьмя примерами; это тестовые свидетельства, не формальное доказательство. CI и типовая валидация отдельно не исследовались. Подробности — evidence.md.
