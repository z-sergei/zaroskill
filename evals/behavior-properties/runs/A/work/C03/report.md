# C03 — проверка устаревшей загрузки

Вердикт: свидетельство вводит в заблуждение; один существенный недостаток высокой важности. Обзор охватывает единственный тест и Upload, без изменения исходников.

**test_upload.py:12–15.** После последнего begin переменная active равна app.current. Условие `active != app.current` никогда не истинно: ни finish, ни assertIsNone не выполняются. Проверка `states > 100` проходит при 210, даже если старый результат заменяет текущий документ. Название теста обещает поведение, которое он не наблюдает.

Доказательство выполнено: исходный `python3 -m unittest discover -v` — 1 тест, OK. В отдельной копии guard в Upload.finish заменён на True; неизменённый тест опять прошёл. Допустимая трасса begin A → begin B → finish B("current-document") → finish A("older-document") дала older-document; независимое сравнение с current-document упало. Та же трасса на исходном Upload прошла. Следовательно, это недостаток теста, не обнаруженная ошибка исходной реализации.

Минимальное исправление: сохранить оба возвращённых token после двух begin, без условного пропуска проверки подать разные документы в обоих разрешённых порядках. После каждого finish проверять document: до активного результата старый оставляет None; активный устанавливает новый документ; последующий старый его сохраняет. Счётчик запусков для этого не нужен. Одно переименование не устраняет пробел.

Оценки: защита от регрессий — **weak** (проверка не достигается); устойчивость к рефакторингу — **mixed** (условие использует внутреннюю схему current вместо наблюдаемого документа); скорость/надёжность — **strong** для локального детерминированного запуска, CI не измерялся; поддерживаемость — **weak** (20 итераций и счётчик скрывают отсутствие полезного действия).

Все команды, коды выхода и контрпример — в evidence.md. Иных тестов в задании нет; произвольные истории не исследовались. Предлагаемое исправление не вносилось, согласно read-only области.
