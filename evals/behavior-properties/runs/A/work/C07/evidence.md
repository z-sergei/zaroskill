# Свидетельства C07

Статус: анализ описанного дизайна; исполнение не нужно и не выполнялось. В C07 только task.md, реализации нет и она не запрошена. Формальная модель не создавалась.

Обязательные свойства из task.md: ticket принадлежит своему независимому жизненному циклу; cancel до отправки ответа исключает отправку; cancel после submission сообщает, что отправка началась; одна логическая отправка имеет неизменный durable message ID и единственный commit на endpoint. После submission ответ должен быть доставлен и ticket стать Answered при заданных предпосылках принятия повторного запроса, возврата receipt, планирования и восстановления worker из pending. Дедлайн и завершение всей службы не обещаны.

Короткая аргументация safety: сериализация cancel/submission исключает неоднозначный порядок этих событий. Если cancel раньше, посылать запрещено; если submission раньше, успешная отмена уже не обещается. Повторные попытки используют сохранённый ID; endpoint делает один commit для него. Изменения принадлежат конкретному ticket, поэтому завершение одного не завершает службу и другие tickets.

Трасса восстановления: submission с ID M → endpoint commit(M), receipt потерян → worker прерван → supervisor восстанавливает durable pending M → повтор send(M) → endpoint возвращает исходный receipt без второго commit → worker записывает Answered. После submission при заданных условиях retry получает receipt и завершает обязанность конкретного ticket. До submission бесконечное ожидание необязательного ответа клиента допустимо.

Это рассуждение по заданным гарантиям, а не выполненная проверка реализации. При появлении кода полезен сценарий commit + потеря receipt + restart, проверяющий тот же ID, единственный удалённый эффект и Answered; отдельно — два сериализованных порядка cancel/submission. Такие тесты здесь не запускались.

Финальная проверка сохранности: исходный task.md не менялся; добавлены только evidence.md и report.md. Исполняемых проверок для анализа не требовалось.
