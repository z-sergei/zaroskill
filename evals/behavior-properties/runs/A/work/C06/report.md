# C06 — бюджет опроса экспорта

Подтверждён дефект дизайна: бюджет пополняется на каждом Pending, поэтому ограничение одной попытки не действует.

Контракт требует максимум 3 poll и StillProcessing после третьего Pending. Трасса: Submit отправляет poll №1 с remaining=3; каждый ответ Pending с suggested=3 устанавливает 3−1=2 и отправляет следующий poll. После третьего ответа отправляется poll №4 вместо StillProcessing. Продолжение этой же трассы с бесконечными Pending удовлетворяет условиям ответа и планирования, но никогда не завершает попытку. Это одновременно конечное нарушение лимита и нарушение прогресса попытки.

Минимальная правка дизайна: устанавливать бюджет 3 только при Submit или явном Refresh, затем уменьшать сохранённый остаток; серверный совет не должен его пополнять. После третьего Pending остаток 0, показывается StillProcessing. Ready прекращает текущую попытку. Постоянная работа самой службы разрешена; срок по часам не обещан.

Следующее полезное свидетельство — тест настоящего контроллера: три Pending → ровно три запроса и StillProcessing, Refresh → новый бюджет; Ready → нет дальнейшего опроса. Это предложения, они не выполнялись. Анализа короткой трассы достаточно; код, тесты и формальная модель не создавались. Область — только описанный дизайн и заданные предпосылки. Детальная трасса — evidence.md.
