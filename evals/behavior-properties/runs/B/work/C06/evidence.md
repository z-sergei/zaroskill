# C06 — анализ без исполнения

Статус: inspected; прочитаны task.md и релевантный раздел temporal-checks.md. Реализация не предоставлена и не запрошена. Тесты, симуляция и формальная модель не запускались: краткая достижимая трасса непосредственно следует из присваиваний в описании. Команды исполнения для этой задачи не нужны.

Контракт из task.md: непрерывно работающий сервис; каждая попытка после submit или явного Refresh делает не более трёх poll, завершает попытку Ready при успехе либо StillProcessing после третьего Pending. Ответ на каждый poll и eventual scheduling гарантированы. Срок в единицах времени не задан.

Состояние одной попытки: remaining, число отправленных poll и показанный результат. Участники: управляющий сервис и отвечающий backend; область — одна попытка, не срок жизни сервиса.

| Событие | remaining после обработки | Отправлено poll | Требуемое/наблюдаемое по дизайну |
|---|---:|---:|---|
| submit | 3 | 1 | начата попытка |
| Pending №1, budget=3 | 2 | 2 | продолжение |
| Pending №2, budget=3 | 2 | 3 | продолжение |
| Pending №3, budget=3 | 2 | 4 | требуется StillProcessing и запрет poll №4; дизайн шлёт №4 |
| каждый следующий Pending, budget=3 | 2 | +1 | состояние повторяется бесконечно |

Трасса допустима: backend явно может бесконечно возвращать Pending с бюджетом 3; каждый ответ приходит, каждый разрешённый poll планируется. Уже конечный префикс доказывает нарушение ограничения числа запросов. Бесконечное продолжение не достигает StillProcessing, хотя предпосылки прогресса соблюдены. remaining не является убывающим вариантом: каждый Pending пополняет его до вычитания.

Минимальное направление исправления, только предложение: устанавливать локальный бюджет 3 при submit/явном Refresh и уменьшать его существующее значение при Pending, не пополняя из ответа сервера. При нуле показать StillProcessing, при Ready завершить попытку. Постоянный процесс при этом продолжает обслуживать будущие события.

Полезное будущее свидетельство: контролируемый backend отвечает Pending три раза; реальная orchestration должна выдать ровно три запроса, на третьем ответе — StillProcessing и никаких новых poll. Дополнительно Ready завершает попытку, а явный Refresh начинает новый бюджет. Это план, а не выполненные проверки; временной deadline и полная формальная модель не требуются.
